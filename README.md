# 数据分析工具（glassdata）

![Python 3.10+](https://img.shields.io/badge/python-3.10%2B-3776AB)
![零第三方依赖](https://img.shields.io/badge/dependencies-0-brightgreen)
![测试 773 项](https://img.shields.io/badge/tests-773%20passed-success)
![License MIT](https://img.shields.io/badge/license-MIT-blue)

只用 Python 标准库实现的本地数据分析工具：读取 Excel / CSV / JSON，完成清洗、统计与可视化，导出一份可双击打开的单文件 HTML 报告。同一套分析逻辑另有浏览器版，两端的解析、统计与清洗结果由差分测试逐格比对。

![界面总览](docs/screenshots/01-overview.jpg)

## 能力一览

| 环节 | 具体内容 |
| --- | --- |
| 读取 | `.xlsx` `.xlsm` `.ods`（桌面版）；`.csv` `.tsv` `.txt` `.json` `.jsonl` `.ndjson`。自动识别编码（含带 BOM 与无 BOM 的 UTF-16）与分隔符，多工作表可指定 |
| 表头 | 自动跳过合并单元格标题行、识别两级表头、对齐开头空行；首个工作表是封面说明页（含「一列短文」形式）时自动落到下一张有数据的表，并给出提示 |
| 清洗 | 去首尾空白、删空行、去重、数字写法归一；缺失填补六种（均值 / 中位数 / 众数 / 前值 / 定值 / 删行）；IQR 1.5 倍法则标记或剔除异常值 |
| 统计 | 描述统计、分位数、皮尔逊相关、字段类型推断、完整度与重复度评估 |
| 图表 | 原生 SVG 手绘：直方图、箱线分布条、相关性热力图 |
| 输出 | 自包含单文件 HTML 报告（零外链、断网可读）；清洗后的 CSV（UTF-8 带 BOM，Excel 双击不乱码） |

## 三种用法

**一、双击运行（Windows，图形界面）**

双击 `main.py`，在窗口里选文件、选工作表、勾选清洗选项，生成报告后自动用浏览器打开。没有图形环境时自动退回命令行，不会崩在半路。

**二、命令行**

```bash
python -m glassdata 订单.xlsx -o 报告.html

# 指定工作表 + 中位数填补 + 标记异常值 + 导出清洗后数据
python -m glassdata 订单.xlsx --sheet 一月 --fill median --outliers flag \
    --clean 订单_清洗后.csv -o 报告.html
```

**三、网页版（无需安装 Python）**

```bash
python -m http.server 8080 -d web
```

打开 `http://localhost:8080`，把 `.xlsx` 或 CSV 直接拖进窗口。解压与解析全部在浏览器内完成，数据不出本机；页面可安装为 PWA，断网也能打开。

## 清洗是可审计的

![清洗面板](docs/screenshots/02-clean-panel.jpg)

默认只做无损动作：去首尾空白、删空行、去重、数字写法归一。填补与剔除必须显式开启，因为自动填补会悄悄改掉原始数据，这是数据分析里最容易出事故的地方。

![清洗结果](docs/screenshots/03-cleaned.jpg)

上图的示例数据启用了「中位数填补」与「IQR 标记」：缺失格 101 → 0，完整度 99.3% → 100.0%，并追加两列异常标记。每一步都留一条日志，报告与页面里并排给出清洗前后的行数、缺失格、重复行与列数。

## 表头不在第一行怎么办

真实表格很少长得像教科书示例。以下三种结构不需要手工改文件：

**合并单元格的标题行。** 首行只有一格内容、且这一格被合并横跨了多列，判为标题行跳过，用它下面一行当表头。

```
┌───────── 销售明细（A1:C1 合并）─────────┐
│ 城市 | 金额 | 日期 |      ← 真实表头
│ 北京 | 1200 | 2026-01-05
```

**两级表头。** 首行有大类分组、第二行是细分字段时，用 `-` 拼成「父-子」形式的列名。

```
│   销售额（A1:B1 合并）   │ 成本 │
│  一月  │  二月  │  一月 │
                ↓
销售额-一月   销售额-二月   成本-一月
```

**封面说明页。** 工作簿第一张表往往只有一句「本表由 ERP 导出」。不指定工作表时逐张尝试，落到第一张能解析出数据的表。

这里有个不容易发现的分支：封面页如果恰好有两行以上文字，它能通过「表头 + 一行数据」的校验，于是被当成一张只有一列的表返回——不报错，也不提示，真正的数据表根本没被读到。页面上会出现一堆看不出问题的文字，用户只会觉得源文件坏了。所以自动选表时，**只有一列且数据不超过 20 行**的工作表先跳过，留作兜底；真的一张都挑不出来才用它，并说明原因。单列清单在现实中极少见，而封面页几乎都是一列短文，这条界线正好落在两者之间。

这些判定都会写进报告的读取提示，不会静默发生。合并区域记的是物理行号，所以文件开头有空行时，行号会先按被删掉的行数对齐再判断——这一步写错，后面的表头就会整体错位一格。

## 三条设计原则

1. **零第三方依赖。** 全仓只 import 标准库：`.xlsx` 用 `zipfile` 与 `ElementTree` 自己解 OOXML，图表用 SVG 手绘，图标用 `zlib` 现场生成。拷到任何装了 Python 的机器上都能跑，不需要 pip install。
2. **不静默改数据。** `180.50` 不会被改成 `180.5`，`12%` 不会变成 `0.12`；异常值默认只标记、不删除。
3. **一套逻辑两个实现，用测试锁住。** Python 引擎与浏览器引擎各自独立，14 套 773 项测试中包含差分对拍：同一批数据集喂给两端，逐格比对解析、统计与清洗结果，并逐字比对每一步的处理日志——文案相同才说明走的是同一条分支，而不是碰巧算出同一个数。

其中 5 套是前端测试，需要 Node；没有 Node 时脚本会把它们标为「跳过」而不是报错。每个测试文件也可单独执行，例如 `python tests/test_engine.py`。

`test_header.py` 的夹具是现场用 `zipfile` 生成的——合并标题行、两级表头、封面页、开头空行、数据区纵向合并、数字表头各造一个文件，避免把二进制样本塞进仓库。同一批夹具会同时喂给 Python 与 Node 两端，比对列名、行数与日志文案。

`test_perf.py` 是性能护栏而非跑分：它只拦 O(n²) 实现回潮（`std` 曾把整列求和写在生成器里，5 万行要 42 秒），阈值设得很宽松，不会因为机器慢一点就红。参考数字：20 万行 × 8 列的分析在开发机上约 3.1 秒，优化前是 7.1 秒，热点在日期列解析、相关矩阵求交和数字识别三处。

## 文件不怀好意时

这个工具吃的是「别人给的文件」——同事发的、系统导出的、网上下载的。`.xlsx` 本质是个 zip，里面的 XML 由别人写。下面四类攻击在 2026 年 10 月这轮排查里逐条实测过，都已封住：

| 攻击 | 不设防的后果 | 现在的做法 |
| --- | --- | --- |
| 解压炸弹 | 321 KB 的包解压出 145 MB，**实测峰值内存 581 MB**；放大十倍就是必然 OOM | 每个部件 512 MB 预算，流式逐块计数，超了立刻停；共享字符串表改 `iterparse`，内存只跟单条字符串有关 |
| XML 实体展开（billion laughs）/ XXE | 400 字节能展开出 3 MB，几十层就吃光内存；外部实体可读本机文件 | 拒绝任何含 `<!DOCTYPE` / `<!ENTITY` 的部件。扫描发生在数据交给解析器**之前**，实体根本轮不到被展开 |
| 伪造坐标 | `r="AAAAAAAA1"` 会算出 83 亿列，按宽度建数组当场吃光内存 | 列号上限 A..XFD（16384），越界立刻报错并指出是哪个坐标 |
| CSV 公式注入（CWE-1236） | 导出后 Excel 双击打开，`=cmd\|'/C calc'!A0` 直接执行，不需要宏、不需要点「启用」 | 导出层给 `= + - @` 开头的格子加单引号前缀，Excel 当文本显示；**纯数字豁免**，`-1200` 不会被改成文本；改了几格会在命令行、窗口和网页提示里说明 |

前端 `xlsx.js` 有同一套前三道防线——网页版是拖进去就能用的入口，用户不会先跑一遍命令行确认文件安全。两端对同一批恶意文件的反应由测试逐条比对。

报告本身也不给注入留缝：payload 用 `json.dumps` 序列化后把所有 `<` 转成 `\u003c`，`</script>` 无法提前闭合脚本块；标题走 `html.escape`。整个工具不联网、不执行文件里的公式与宏、不把压缩包解到磁盘。

## 已知限制

- 旧版 `.xls`（OLE 复合文档）不支持，会明确提示另存为 `.xlsx` 或 CSV；
- 表头识别只覆盖「合并标题行 + 单行表头」「两级表头」「首张封面页」这三种常见结构。三行以上的多级表头、斜线表头、表头里混空列仍需先手工整理；
- 「跳过封面页」靠「只有一列且不超过 20 行」判定：两列以上的说明页、或把 20 行以上的单列正文放在首张，仍可能被当成数据表。遇到这种文件用 `--sheet` 显式指定工作表最稳；
- 多工作表不合并，一次只分析一张表（网页版可在下拉里切换，切换会重新解析一次）；
- 合并单元格只在表头区域做特殊处理，数据区内的纵向合并不做向下填充，空格保持为空，以免替用户编造数据；
- 网页版单次上限 50 万行，超过会提示改用桌面版；
- 单个 XML 部件解压后上限 512 MB：极少数「行数不多但单元格文本极长」的文件可能触顶。这时报错会说明是哪个部件、超了多少，不会静默截断；
- 导出的 CSV 里，以 `= + - @` 开头的非数字单元格会被加单引号前缀（Excel 当文本显示）。这是有意的改动，格数会在三处提示里说明；需要完全原始的内容请从源文件取；
- 只做描述性分析与清洗，不做建模与预测。

## 部署网页版

`web/` 是完整静态站点，可发布到任意静态托管。用 GitHub Pages 时：Settings → Pages → Source 选择 `main` 分支、目录选择 `/web`。仓库已内置 `web/.nojekyll`，避免 Jekyll 处理干扰静态文件。页面内所有资源路径都是相对的，因此挂在 `/仓库名/` 这类子路径下也能正常工作。
